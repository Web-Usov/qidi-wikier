# QIDI Wikier

Инструменты и структура для превращения Telegram-чатов о QIDI Q2, QIDI BOX и филаментах в проверяемую базу знаний.

## Что уже есть

- потоковое чтение больших Telegram JSON без загрузки файла целиком в память;
- нормализация сложного поля `text` из экспорта Telegram Desktop;
- удаление очевидного флуда, объявлений, сервисных сообщений и пустых медиа;
- восстановление точных цепочек через `reply_to_message_id`;
- обнаружение служебных ID форумных топиков Telegram;
- консервативное восстановление сообщений без reply по времени, автору, теме и ключевым словам;
- явная маркировка всех эвристически восстановленных связей;
- первичная тематическая классификация;
- разбиение результата на цельные Markdown-пакеты;
- карантин сомнительных сообщений;
- отчёт об удалении и статистика;
- полный JSONL и Markdown-выборка контекстных связей для ручной проверки;
- схема будущих карточек знаний и доказательств.

## Требования

- Node.js 22.6 или новее;
- исходные Telegram JSON на локальном диске.

Внешние npm-зависимости не используются.

## Быстрый старт

```bash
mkdir -p sources prepared
cp /путь/к/qidi_general_chat.json ./sources/

npm run prepare -- \
  --input ./sources/qidi_general_chat.json \
  --output ./prepared/general \
  --source-name qidi_general_chat
```

Дополнительные параметры:

```text
--max-chars 600000
--context-window-minutes 12
--same-author-window-minutes 45
--min-context-score 4.0
--review-sample-size 100
```

Порог `--min-context-score` намеренно консервативный. Чем он выше, тем меньше риск ошибочно объединить соседние разговоры, но тем больше полезных сообщений останется отдельными цепочками.

## Результат

```text
prepared/general/
├── manifest.json
├── statistics.json
├── chunks/
│   ├── qidi_general_chat_001.md
│   └── ...
├── quarantine/
│   └── uncertain_messages.jsonl
├── review/
│   ├── context_links.jsonl
│   └── context_links_sample.md
└── skipped/
    └── removal_report.json
```

По умолчанию размер одного Markdown-пакета ограничен примерно 600 000 символов. Граница никогда не разрывает отдельную цепочку обсуждения.

Перед созданием Wiki необходимо просмотреть `review/context_links_sample.md`. В него попадают связи с наименьшим эвристическим баллом. Ошибки следует исправлять настройками или алгоритмом, а не вручную в производных Markdown-файлах.


## Ограничения текущей версии

- Фильтрация не определяет истинность советов и не заменяет редакторскую проверку.
- Контекстные связи без Telegram reply являются предположениями и всегда помечаются.
- Вложения не анализируются, если сами файлы не были выгружены.
- Подготовленные пакеты являются слоем доказательств, а не готовой энциклопедией.
- Следующий этап — создание редакторских карточек знаний и связывание их с доказательствами.

Подробности: [архитектура](docs/ARCHITECTURE.md) и [схема знаний](docs/KNOWLEDGE_SCHEMA.md).
