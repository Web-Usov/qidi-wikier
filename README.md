# QIDI Wikier

Инструменты для превращения Telegram-чатов о QIDI Q2, QIDI BOX и филаментах в проверяемую базу знаний.

## Что делает версия 0.4

- потоково читает большие Telegram Desktop JSON без загрузки файла целиком в память;
- удаляет очевидный флуд, объявления, сервисные сообщения и пустые медиа;
- сохраняет точные цепочки через `reply_to_message_id`;
- распознаёт служебные ID форумных топиков Telegram;
- извлекает материалы, принтеры, компоненты, симптомы и бренды;
- строит отдельный нетранзитивный граф предположительных связей между верхнеуровневыми сообщениями;
- отклоняет конфликты материалов, принтеров, дубли и неоднозначные связи;
- рассчитывает отдельную оценку `knowledgeValue`;
- формирует стратифицированную выборку связей `low / medium / high`;
- извлекает из сильных точных цепочек кандидаты доказательств;
- классифицирует кандидаты как `ready`, `question-only`, `needs-context` или `reference-only`;
- отмечает типы содержимого: вопрос, наблюдение, рекомендация, результат, конфигурация и ссылка;
- сохраняет дословные температуры, скорости, расходы, размеры, проценты, длительности и версии;
- присваивает только предварительную надёжность `C` или `D` и всегда требует редакторской проверки;
- помечает отсутствующие медиа, внешние ссылки и утверждения, скопированные из нейросетей.

## Требования

- Node.js 22.6 или новее;
- исходные Telegram JSON на локальном диске.

Внешние npm-зависимости не используются. `npm install` не обязателен.

## Быстрый старт

```bash
mkdir -p sources prepared
cp /путь/к/qidi_common_chat.json ./sources/

npm run ingest -- \
  --input ./sources/qidi_common_chat.json \
  --output ./prepared/common \
  --source-name qidi_common_chat
```

Дополнительные параметры:

```text
--max-chars 600000
--context-window-minutes 12
--same-author-window-minutes 45
--min-context-score 4.0
--min-score-margin 0.75
--min-evidence-value 0.6
--review-sample-size 120
```

`--min-score-margin` задаёт минимальный отрыв лучшего кандидата от второго.

`--min-evidence-value` задаёт минимальный `knowledgeValue` точной цепочки, при котором создаётся кандидат доказательства. Значение `0.6` соответствует текущей границе высокой ценности.

## Результат

```text
prepared/common/
├── manifest.json
├── statistics.json
├── chunks/
│   ├── qidi_common_chat_001.md
│   └── ...
├── evidence/
│   └── candidates.jsonl
├── quarantine/
│   └── uncertain_messages.jsonl
├── review/
│   ├── context_graph.jsonl
│   ├── context_links_sample.md
│   └── evidence_candidates_sample.md
└── skipped/
    └── removal_report.json
```

В `chunks` находятся только точные Telegram reply-цепочки. Предположительные связи перечисляются как метаданные, но не добавляют чужой текст внутрь цепочки.

`evidence/candidates.jsonl` содержит структурированные черновики доказательств со ссылкой на точную цепочку, исходные сообщения, извлечённые сущности, параметры и флаги проверки.

`review/evidence_candidates_sample.md` — стратифицированная выборка по четырём статусам для ручной оценки правил извлечения.

## Ограничения

- Алгоритм не определяет истинность технических советов.
- Предварительная надёжность `C/D` не является опубликованной оценкой доказательства.
- Уровни `A` и `B` никогда не назначаются автоматически.
- Отсутствующие фотографии и видео не анализируются.
- Кандидаты доказательств ещё не являются карточками Wiki.
- Следующий этап — редакторская проверка выборки, затем группировка подтверждённых доказательств в кандидаты карточек знаний.
